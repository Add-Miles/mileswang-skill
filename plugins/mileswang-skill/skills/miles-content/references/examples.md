# Worked Revisions and Checks

These are concrete, illustrative inputs and outputs. They do not claim that the events happened to the current user.

## Example 1: replace a trend opening with the real scene

Source facts supplied in the example:

- Format: 45-second creator video.
- Scene: at 22:40, the creator copied the same query between a coding agent and an X search tool four times.
- Want: stay inside the coding agent while researching a post.
- Obstacle: the required search capability lived in a different tool.
- Action: the creator packaged one narrow command that calls the search tool and returns the result.
- Verified: the command worked on one local input.
- Not verified: public installation, repeat reliability, or any time saved.

Weak draft:

> AI is changing everything. In this fast-moving era, creators must embrace tools and break model boundaries. So I built a revolutionary skill that dramatically improves efficiency.

Direct verdict:

> The direction is inflated. The source proves one broken workflow and one local run, not a revolution or a measured efficiency gain.

Reduced revision:

> Last night at 10:40, I copied the same question between my coding agent and an X search tool four times. The problem was not that either model was weak; the workflow was broken. I packaged one narrow command: the coding agent keeps the task, the search tool returns the X result. It worked on my local test. Public installation and repeat stability still need verification.

Why it is stronger:

- It opens on an observable action.
- The conflict is a broken workflow, not a vague technology trend.
- It preserves the evidence boundary instead of inventing time savings.
- It ends at the demonstrated result without forced uplift.

## Example 2: remove an unsupported performance claim

Source facts supplied in the example:

- A current repository page visibly shows more than 1,000 stars.
- The source does not establish when the stars were gained.
- The creator wants a short announcement.

Draft:

> We broke 1,000 stars in one week, proving this is the most useful skill collection in the community. This is only the beginning.

Direct verdict:

> “In one week,” “most useful,” and the concluding claim are unsupported. Keep the observable milestone and tell people what they can inspect.

Reduced revision:

> The repository now shows more than 1,000 stars. I have kept the skills open so you can inspect the workflows and decide which ones are useful for your own setup.

## Fidelity-cleanup example

Transcript input:

> 我当时应该是晚上十点多，然后复制了三次还是四次，反正来回切挺麻烦的。

Fidelity cleanup:

> 我当时应该是晚上十点多，复制了三次还是四次 `[待确认]`。来回切换挺麻烦的。

Do not silently rewrite “三次还是四次” as an exact count.

## Final content check

- [ ] Use only supplied or verified facts.
- [ ] Preserve ambiguity in fidelity mode.
- [ ] State one audience-facing promise.
- [ ] Show a scene, want, obstacle, and consequence or turn.
- [ ] Remove generic openings, repetition, and oversized conclusions.
- [ ] Avoid default slogans and decorative “golden lines.”
- [ ] Keep one causal spine throughout the piece.
- [ ] Separate hard factual errors from soft style issues.
- [ ] Compare the revision against the same source, not against an imagined ideal.
- [ ] Return a piece that can be used in the stated format.
